# 特征字典与实现状态

更新：2026-11-22。`features.py` 已实现并在全量保留版本上运行 24 项七日窗口特征。三组本地样本及公开汇总由 `feature_audit.py` 生成，详见[窗口特征与样本核验](10_窗口特征与样本核验.md)。旧去重口径 LR 指标仍失效；固定样本上的新 LR 对照已完成，见[实验报告](../reports/lr_baseline_report.md)。

## 共同定义

历史窗口为 `[cutoff-7天, cutoff)`，标签窗口为 `[cutoff, cutoff+7天)`。用户商品候选只来自历史窗口。行为码 1/2/3/4 暂按浏览/收藏/加购/购买解释，语义仍待确认。所有计数保留真实重复事件；ID、标签均不作为数值特征。

| 层级 | 字段 | 精确定义 | 已实现 |
|---|---|---|---|
| 交互 | pair_events | 用户商品对历史事件总数 | 是 |
| 交互 | pair_pv / pair_fav / pair_cart / pair_buy | 该对行为码 1/2/3/4 的事件次数 | 是，4 项 |
| 交互 | pair_active_days | 该对发生行为的自然日去重数 | 是 |
| 交互 | pair_distinct_hours | 该对发生行为的时间桶去重数 | 是 |
| 交互 | pair_recency_hours | 截点减该对最后行为时间，单位小时 | 是 |
| 用户 | user_events | 用户对所有商品的历史事件数 | 是 |
| 用户 | user_pv / user_fav / user_cart / user_buy | 用户行为码 1/2/3/4 的事件次数 | 是，4 项 |
| 用户 | user_distinct_items | 用户历史交互商品去重数 | 是 |
| 用户 | user_active_days | 用户历史活跃自然日数 | 是 |
| 用户 | user_recency_hours | 截点减用户最后行为时间，单位小时 | 是 |
| 用户 | user_buy_recency_hours | 截点减最后一次行为码 4 的时间；未发生时为 168 | 是 |
| 用户 | user_has_buy | 历史是否有行为码 4，取 0/1；区分间隔 168 小时与未发生 | 是 |
| 商品 | item_events | 商品历史事件数 | 是 |
| 商品 | item_users | 商品历史交互用户去重数 | 是 |
| 商品 | item_buy | 商品行为码 4 的事件数 | 是 |
| 商品 | item_buyers | 商品行为码 4 的用户去重数 | 是 |
| 商品 | item_active_days | 商品发生行为的自然日去重数 | 是 |
| 商品 | item_buyer_rate | item_buyers / item_users，历史内比例，不平滑 | 是 |
| 标签 | label | 同一对在标签窗内是否观测到行为码 4；不输入模型 | 是 |

上述特征共 8 项交互、10 项用户、6 项商品特征。候选商品的 item_users 必然大于 0，因此比例分母非零。比例不是曝光转化率；原始特征未做标准化、重采样或缺失学习填补。后续缩放等处理只能在训练集拟合；0/1 与比例特征应明确选择变换方式。

`BASELINE_FEATURES` 保留原基线的 10 项字段及顺序，供后续公平对照；新增特征不是已经证明有效，须在验证集比较。当前训练集相关性图仅展示原值 Pearson 相关，不等于模型重要性或预测能力。

## 不可直接输入预测模型的表

流水线生成的 `user_summary` 和 `item_summary` 是整个观察期的 EDA 汇总，包含预测截点后的信息，禁止用作预测特征。当前特征模块只读取标准化事件，在 SQL 内先截断历史，再分别聚合。

## 后续扩展，尚未实现

- 连续活跃日、类目偏好、近期热度变化与类目历史统计。
- 同小时并列桶的序列间隔与转移，不任意排序同小时记录。
- SVD、商品共现、训练集 OOF 目标编码及冷启动评价。
- 更完整的单项特征消融与互信息分析。六项历史特征组合对照已完成，见下文。

特征去留只能由训练/验证集决定，测试窗口的基础质量统计不用于选择特征或调参。时间分组允许同一用户出现在多个窗口，当前不代表冷启动泛化能力。
