# 第一阶段文献调研笔记

更新：2026-11-13。已核对下列指定版本的任务、方法与实验章节。本文件是文献调研交付，不代表模型复现或本人已掌握全部内容；讲解练习由实习生完成。原文件名保留以兼容既有链接。

## 1. Wide & Deep：交叉特征与嵌入的联合学习

来源：[Cheng 等，2016，v1，第 3—5 节、表 1](https://arxiv.org/html/1606.07792v1)。

**原文要点**：任务是 Google Play 曝光后的应用获取预测。Wide 使用原始及交叉特征，Deep 使用嵌入与多层网络，两路 logit 相加，通过共同的逻辑损失联合训练。简式为 `p = sigmoid(w·[x,φ(x)] + v·h(x) + b)`。线上比较持续三周，Wide、Deep、联合模型的离线 AUC 分别为 0.726、0.722、0.728；联合模型线上获取量相对 Wide 提升 3.9%。这是原场景结果，不能当作本项目收益。

**本项目设计推演（未实施）**：

- 任务改为历史候选用户—商品对的未来七日购买预测；不存在曝光日志，不能沿用曝光负样本。
- 三项可迁移设计：增加近期加购与商品热度的交叉项；为商品/类目建立训练集词表和未知值；固定相同样本比较线性、深层和联合结构。
- 两项限制：商品长尾导致嵌入训练不足；缺少曝光，评价仅适用于既定候选范围。
- 自拟计算例：Wide logit 为 0.6、Deep 为 0.4、偏置为 -0.5，总 logit 为 0.5，sigmoid 约 0.622。这只是机制演示，不是训练输出。

**阅读判断**：离线排序指标与线上收益衡量不同目标，不能用 AUC 的小幅增加直接推算购买增长；上线收益必须另行实验。

## 2. DIN：随候选商品变化的兴趣表示

来源：[Zhou 等，2017，v2，第 3—6 节、表 3](https://arxiv.org/html/1706.06978v2)。本次固定此版本，避免混用其他版本的实验数字。

**原文要点**：任务是广告点击预测，以两周日志训练、随后一天测试；局部激活单元按候选对象为历史行为加权，简式为 `u(q)=Σ a(eᵢ,q)eᵢ`，随后预测点击并优化逻辑损失。表 3 的 GAUC：基础模型 59.59%，加自适应正则 60.31%，DIN 加该正则 60.60%，再加 Dice 为 60.83%。全配置较基础模型增加 1.24 个百分点；其中注意力的增量应与同正则基线比较，不能把全部增量归因于注意力。正文个别增益数字与表格不一致，本笔记以表格为准。

**本项目设计推演（未实施）**：

- 三项可迁移设计：历史商品/类目共享嵌入；候选相关加权聚合；用统一正则、训练预算做逐项比较。
- 两项限制：小时级时间无法辨别同小时顺序；只有行为没有曝光，不能宣称预测真实 CTR。
- 自拟计算例：历史向量为 `(1,0)`、`(0,1)`，对候选 A 的权重为 2、0.5，则兴趣向量为 `(2,0.5)`。换候选后权重可变；这些数值是人为设定，权重不必合计为 1。

**阅读判断**：候选相关性不等于时间顺序。后续若使用 DIN，要单独验证时间间隔特征；GAUC 还必须明确分组、权重及单类分组的处理，不能与普通 AUC 直接比较。

## 3. BST：行为序列中的相互关系

来源：[Chen 等，2019，v1，第 2—3 节、表 4](https://arxiv.org/html/1905.06874v1)。

**原文要点**：任务是淘宝排序阶段的点击预测；八天日志中前七天训练、最后一天测试。商品/类目及位置特征经 Transformer，再结合其他特征用 MLP 和交叉熵预测。核心为 `Attention(Q,K,V)=softmax(QKᵀ/√d)V`。WDL、平均聚合序列、DIN、单层 BST 的 AUC 为 0.7734、0.7846、0.7866、0.7894；单层 BST 相对 WDL 的线上 CTR 增益 7.57%，平均响应时间从 13 增至 20 ms。两层、三层 AUC 为 0.7885、0.7823，更深并未更好。

**本项目设计推演（未实施）**：

- 三项可迁移设计：以预测截止时刻为界构造历史；显式加入小时差与 padding mask；先比较平均聚合与单层模型，再决定复杂度。
- 两项限制：同小时没有可信顺序，应聚合或共享时间位置；仅一万用户且商品稀疏，原文的大规模效果不保证可迁移。
- 自拟计算例：某查询对两段历史的 softmax 权重为 0.75、0.25，值向量为 `(1,0)`、`(0,1)`，输出为 `(0.75,0.25)`；后续还需投影、前馈与预测层，此例不是完整模型复现。

**阅读判断**：模型效果和计算代价必须一起比较。小时并列事件不能按文件行号冒充真实先后，未来标签不能进入历史序列。

## 4. 三篇文献对本项目的共同启示

| 比较维度 | 本项目采用的判断 |
|---|---|
| 研究问题 | 三篇侧重推荐排序；本项目当前是七日购买预测，先明确候选、时间窗和标签 |
| 特征与复杂度 | 先检查交叉统计是否有效，再决定是否需要候选注意力和序列模型 |
| 评价 | 时间划分为主；记录 ROC-AUC、AP、Precision、Recall 和候选覆盖率，统一候选集再比较 |
| 公平实验 | 相同样本、特征可见截止时间和调参预算；只改一个组件，避免混淆收益来源 |
| 数据工程 | 保留原始层，记录去重前后计数；历史窗口边界与小时并列规则必须可复查 |
| 证据边界 | 论文指标、演示数值、项目实测三者分别标注；不把论文提升写入项目成果 |

这些是基于本项目字段条件提出的设计建议，不表示已完成后续模型训练。本阶段到文献调研与数据口径核查为止。

## 5. 提交前本人讲解提纲

1. 为什么没有曝光不能直接照搬 CTR 的负样本？因为没有交互不等于看到后未点击。
2. 为什么 DIN 需要候选商品？同一用户的不同历史对不同候选有不同相关性。
3. 为什么不能现在断言 BST 最好？本数据、任务、规模、时间精度与论文不同，尚无同条件实验。
4. 为什么清洗口径优先于模型？小时内重复行为的合并会改变频次特征和事件统计。
