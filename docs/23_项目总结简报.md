# 项目总结简报（结项准备版）


## 项目总结简报

结项准备版 / 成果截至 2026-11-27 / 计划下周完成结项核对

项目目标：基于行为日志建立可复现的数据处理、未来七日目标预测及双看板分析流程。本项目已形成离线研究与公开演示成果；最终验收和业务收益结论尚未完成。

| 核心结论 | 证据与含义 |
| --- | --- |
| 先守住正确数据口径 | 依据带教反馈撤销小时内直接去重，12,256,906 条有效事件全部保留。同用户＋商品＋行为＋小时最大 22 次，无超过 100 次组。重复交互不能直接当错误。 |
| 先看候选覆盖，再看分类排序 | 验证候选覆盖仅 11.87%。候选外 18,743 个目标对无法靠调整分类阈值解决；需确认是否包含未交互商品。 |
| 总体提升不等于目标问题解决 | HGB 24→30 特征 AP 0.039328→0.043185、Top-5,060 命中 367→382；较早且低频组仍 0/896，未替换基线。 |
| 类别权重需要实证比较 | 相同预算下 LR 未加权命中 312，高于加权的 241；不能只凭类别不均衡就认定加权一定更好。 |

补充发现：HGB 小样本学习曲线显示明显训练／验证差距；增加训练量后差距收窄。推理与资源已有本机初测，但不能据此承诺线上服务性能。

交付：可访问、可筛选、可下载的双看板；规范化代码与版本记录；特征字典、实验协议、数据指纹、结果图及阶段周报。原始明细和模型文件不公开上传。


## 01 / 方案亮点与可复用方法

| 方法 | 本项目落地 | 可复用规则 |
| --- | --- | --- |
| 口径驱动的数据质量 | 正常重复保留；异常规则、计数守恒、格式核对分开处理。 | 先问记录代表什么，再决定删除、隔离或保留；记录更正不抹去历史。 |
| 按时间构建预测任务 | 历史七日特征、未来七日标签；严格截点和候选范围。 | 先冻结样本单位、时间边界和标签，再建模；防止未来信息进入特征。 |
| 控制变量与分层判断 | 24／30 特征、LR 权重对照、相同全局预算、较早低频分组。 | 同时评估总体和目标群体；不同预测量下不直接比较召回。 |
| 证据可追溯 | 协议先记录、数据及模型哈希、代码检查、单元测试、结果留档。 | 将“配置—输入—运行—指标—解释”串成可核查链条。 |
| 分析与展示分离 | 看板读取匿名汇总；固定模型窗口不随任意日期重算。 | 为图表标清单位、分母、筛选范围和数据来源；下载数据与页面对账。 |

标准流程：业务口径 → 数据审计 → 时间窗与候选 → 简单基线 → 受控对照 → 等预算与分组诊断 → 独立评价 → 交付验收。当前独立最终评价与业务决策条件尚未全部具备。

工程价值在于分析能被复查和继续迭代，而不是只交付一个分数。特征分箱仅用训练历史确定边界，空箱和小样本标记保留；学习曲线与错误案例也写清抽样和解释限制。


## 02 / 局限、优化优先级与结项安排

| 优先级 | 局限与下一步 |
| --- | --- |
| P0：确认业务边界 | 确认行为码、时区与采样完整性；明确未交互商品是否在任务内、预算和误报／漏报成本。没有这些条件不固定业务阈值。 |
| P1：可靠评价 | 冻结目标方案与判定规则；用未参与开发的新时间窗口验证稳定性。既有验证已多轮探索，11/17 LR 测试结果不作为新留出证据。 |
| P2：针对性优化 | 优先研究候选扩展和较早／低频目标；用等预算及目标分组评估增益，再考虑正则化、特征与校准。数据字段不足时不虚构金额、曝光或注册留存。 |
| P3：生产化验证 | 若进入上线阶段，再做目标环境的并发、冷启动、漂移监控及资源压测；当前 Streamlit 是离线结果展示。 |
