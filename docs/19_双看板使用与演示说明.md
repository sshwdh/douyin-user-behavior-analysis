# 双看板使用与演示说明

更新：2026-11-25。

[在线双看板](https://rundashboardpy-p5s7wh8jdprnz7a9bx6f4h.streamlit.app/) | [项目仓库](https://github.com/sshwdh/douyin-user-behavior-analysis)

## 五分钟演示路径

1. 打开“用户行为与特征”，说明全期 12,256,906 条事件及重复交互全部保留的规则。
2. 选择日期与行为，查看每日趋势、星期与小时热力图；切换“类目与长尾”，下载当前类目汇总。
3. 展开“特征工程 · 实现目录与完整下载”，查看实现状态并下载特征核对表。未实现项不代表已经进入模型。
4. 切换“模型验证与误差”，说明固定验证窗口和用户商品对标签；查看模型总览与 PR/ROC。
5. 比较相同全局预算的命中数，说明候选覆盖不足、分数未校准及待确认业务口径。

## 如何正确阅读

| 内容 | 统计与联动范围 | 常见误读 |
|---|---|---|
| 顶部数据概况 | 全观察期固定值 | 不随日期筛选重算，不是筛选失效 |
| 趋势、小时及类目 | 所选日期与行为；具体分母见图注 | 次数不等于用户数、曝光或订单数 |
| 四类行为结构 | 随日期变化，完整展示四类行为 | 不是要求依次发生的漏斗 |
| 用户回访 | 首次观测队列，成熟队列计算相应 Dn | 不是注册留存，未成熟留空而非零 |
| 模型指标 | 固定验证窗口，随模型选择变化 | 不受行为页任意日期筛选驱动 |
| 全局 Top-K | 全部候选排序后取前 K 对 | 不等于每个用户推荐 K 个商品 |
| 曲线 | 展示点抽样，指标由全部预测计算 | 不对展示曲线积分替代 AP/AUC |
| 权重与系数 | 固定 LR 对照与系数解释 | 不是因果分析、SHAP 或已校准概率 |

## 下载与复核

- 当前类目汇总 CSV 应与当前筛选事件数一致；11/24 验收例：2025-11-18、行为码 4，合计 3,730 条。
- 完整特征表是固定实现核对表，不受日期筛选影响。在线下载文件与仓库 Excel 的 SHA-256 已于 11/24 核对一致。
- 看板公开汇总数据，不包含原始 CSV、用户级预测或本地模型文件。复现完整训练需要本地原始数据及对应流程。

## 访问问题排查

11/25 实际遇到平台休眠页，提示 “This app has gone to sleep due to inactivity”。若出现该页面，点击 “Yes, get this app back up!” 并等待恢复。若仅页面加载未完成，先刷新并等待。若仍无法访问，保留错误提示与发生时间，改用仓库和 PDF 查看成果，再核查云端日志与网络。页面加载失败不等于数据结果错误，也不能仅凭首页返回成功判断功能正常。

已通过的公网验收记录见 [11/24 云端验收](../reports/dashboard/2026-11-24_cloud_acceptance.json)。当天复查情况另见每日记录。

发布维护：若平台日志显示已拉取新提交，但新会话仍未出现预期页面变化，需在管理面板检查运行状态，必要时重启应用，再以实际页面和交互验收确认生效。不能只以 GitHub 推送成功作为线上生效证据。

新增分析入口：用户行为页底部“特征与目标 · 分箱正例率”；模型页底部“用户与商品分层 · 三模型表现”。两个模块固定验证窗口，支持维度切换和当前汇总下载。详细口径见[新增分析说明](21_特征关联与用户商品分层.md)。
