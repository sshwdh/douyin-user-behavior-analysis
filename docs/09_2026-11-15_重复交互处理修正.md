# 重复交互处理修正记录

日期：2026-11-15。原因：带教指出，同一用户一小时内可以多次执行相同行为，不能把相同小时四元组的记录全部合并。此前全局去重会减少合法事件频次，原事件统计及模型结果不再作为当前结论。

## 规则与待确认事项

取消四元组去重。暂按“用户＋行为＋自然小时”跨商品累计，频次不超过 100 全部保留，超过 100 的整组记录进入本地隔离区。不是截断保留前 100 次，也不是删除该用户其他小时或其他行为的记录。原始 CSV 不变。

老师提供了“超过 100 次”的阈值示例，尚未明确是否包含商品维度以及超阈值后的具体处置。当前分组与整组隔离是可逆的暂行实现，需业务确认；超阈值仅代表疑似异常，不证明错误或恶意。

| 分组 | 最大频次 | 超过 100 次的组 | 涉及记录 |
|---|---:|---:|---:|
| 用户＋行为＋小时 | 792 | 9,681 | 1,316,083 |
| 用户＋商品＋行为＋小时 | 22 | 0 | 0 |

如果采用包含商品的分组，本批数据在阈值 100 下全部通过频次筛查。不能混用这两种口径。详见 [频次分布](../reports/hourly_frequency_profile.csv) 和 [阈值敏感性](../reports/threshold_sensitivity.csv)。

## 本次重跑结果

原始 12,256,906 条，无效 0 条，隔离 1,316,083 条，保留 10,940,823 条；正常重复合并数 0。隔离率约 10.74%，主要是浏览行为；购买事件全部保留，共 120,205 条。原小时去重结果为 6,213,379 条，购买事件为 106,678 条，二者已经停用。

重建范围：事件 Parquet、用户/商品汇总、SQLite、聚合 CSV、八张图、分析报告及修订周报。SQLite 四元组索引改为非唯一索引，避免数据库再次强制去重。

原始文件与隔离明细仅保留本地，隔离文件为 `data/processed/quarantined.parquet`。公开仓库只保留汇总和说明。旧产物位于 `reports/history/2026-11-13_hourly_dedup/`；旧 PDF 不覆盖，新 PDF 按修订日期命名。

## 模型影响

旧 LR 的频次特征和候选集合来自错误去重口径，指标已标记失效并归档。当前不引用其结果证明新口径效果；待规则确认后重跑。

## 复现

```bash
python -m douyin_analysis.pipeline --input ../user_behavior.csv --threshold 100 --scope user_behavior_hour
python scripts/analyze_hourly_frequency.py
python -m douyin_analysis.sqlite_store
python -m douyin_analysis.plots
python -m douyin_analysis.reporting
python scripts/validate_outputs.py
python scripts/run_checks.py
python scripts/build_weekly_pdf.py
```

另一种分组可指定 `--scope user_item_behavior_hour`，每次切换都必须重建下游产物并核验，不能只改文字。
